# Decisions

1. **Legacy files left in `Studyverse/`.** Master rule 10 and 01 Part B.9: move only if the app still runs without them. The deploy source is unknown (no Vercel/CI config in repo), so nothing is moved before Phase 8.
2. **Shared package compiles to `dist/`.** `@studyverse/shared` exports built JS + types so the API (Node ESM, `tsc` build) and web (Vite) consume the same artifact. Root scripts (`dev`, `typecheck`, `test`, `build`) build shared first. Alternative: export raw TS and bundle the API (rejected: adds a bundler).
3. **API uses `NodeNext` + `.js` import suffixes; web uses `Bundler` resolution.**
4. **Single Vite copy.** `vite@^6` is declared at the root as well as in web so vitest 3 does not pull a second Vite 5 (that caused a type clash).
5. **Fonts** loaded locally via `@fontsource/cinzel` (display) and `@fontsource/lato` (body): one display + one body face, no external requests.
6. **Anime.js not installed yet.** It is added in the phase that uses it (Phase 5/6) so the installed version's API can be verified from its docs.
7. **Rate limiting, Prisma, Supabase, auth** are intentionally absent: they belong to Phase 3.
8. **`db:*` scripts** exist but exit with a clear "not wired until Phase 3" message instead of faking success.
9. **`dangerouslySetInnerHTML` is banned by ESLint** in `apps/web` (hard rule 7).
10. **Balance reminder (for Phase 3/4):** XP curve ambiguity (cumulative vs per-level) must be decided in Phase 3 and unit-tested.

## Phase 3 (database, auth, API plumbing)

11. **XP table is CUMULATIVE.** `[0,100,250,450,...,3250]` is the total XP at which each level is reached (level 2 at 100, level 3 at 250). A level's cost is the difference (100, 150, 200 ...), fixing the old bug where per-level XP was compared with cumulative thresholds (old 2→3 cost 250, now 150). Past the table each level adds 500 to the cumulative total, as the spec says. Side effect to know about: the cost of 10→11 is 550 but 11→12 is 500, a small dip; change `stepAfterTable` in `balance.ts` if you want it to keep rising. Alternative rejected: per-level costs (would double-count the table).
12. **Level/in-level XP are derived from `totalXp`** by one pure function (`levelFromTotalXp`) in `packages/shared`; `grantXp` writes level/currentLevelXp from it and `/progress` recomputes them, so they cannot drift.
13. **`grantXp` concurrency:** it locks the player's `PlayerProgress` row (`SELECT … FOR UPDATE`), then inserts the ledger row with `ON CONFLICT DO NOTHING` on `(userId, sourceType, sourceId)`. A repeat returns the ORIGINAL outcome (`granted:false`, stored amount/levels) and changes nothing. The ledger row stores `levelAfter / levelsGained / skillPointsAwarded` for that reason. Passing a transaction client makes the grant part of a bigger transaction (battle finish).
14. **Token verification = JWKS with `jose`** (asymmetric keys, `ES256/RS256/EdDSA` only; issuer `<SUPABASE_URL>/auth/v1`, audience `authenticated`, `role=authenticated`, `sub` must be a UUID). Every failure is a generic 401. Projects still on the legacy HS256 shared secret would need a different verifier; the new publishable/secret key setup uses JWKS.
15. **Secure by default:** every `/api/v1` route except `/health` requires a token (so unknown paths return 401 to anonymous callers, 404 to signed-in ones). User ids come only from the token; routes take no user id.
16. **Display names:** 3–20 chars, letters/digits/space/`_`/`-`, no `@`, unique case-insensitively via a `displayNameKey` column (Prisma cannot express a `lower()` unique index). New players get `Adventurer-<8 hex of id>`; `showOnLeaderboard` defaults to false (opt-in).
17. **Equipment ownership is enforced by the database:** `Equipment(weaponItemId, userId) → PlayerItem(id, userId)` composite FKs with `NO ACTION` (SET NULL would also null the NOT NULL `userId`). Flashcard `userId` is denormalized from the deck and is checked in the service layer.
18. **RLS on every table, zero policies**, plus `REVOKE ALL … FROM anon, authenticated` when those roles exist (Supabase). Prisma uses a privileged role, so authorization is the API's job (README).
19. **Rate limits** are in-memory per process with separate buckets (general / auth / battle-answer / import). `TRUST_PROXY` must be set behind a proxy. Use a shared store if the API is ever scaled horizontally.
20. **Env files are per app** (`apps/api/.env`, `apps/web/.env`); the root `.env.example` was removed. The API never needs the Supabase secret key.
21. **Migration SQL was generated by a script, not by `prisma migrate`**, because the sandbox could not download Prisma's schema engine. Constraint/index names follow Prisma's conventions. See HANDOFF for the one command that confirms there is no drift.
22. **Question bank and quest definitions are not seeded yet** (Phase 4). The seed currently covers 12 items, 9 skills and 12 achievements.

## Phase 4 (core modules: API)

23. **`needsReview` questions stay in the game.** The seed flags suspicious entries (e.g. `hist-h-007`) but never edits them. Claim quizzes and (later) battles still use them, and the claim result offers "Report this question" (`POST /questions/:id/report`). Alternative: exclude until approved (rejected: shrinks the bank for no gain while reports exist).
24. **Ineligible sessions are stored as `abandoned` with `outcomeReason`** (`not_enough_time` below 80% of the plan, `not_enough_focus` below 0.5). Nothing is paid and the reason is shown in the UI and the history.
25. **The claim quiz is a snapshot.** Bank quizzes are built when the session is finished, review quizzes when it is created; choices are shuffled and stored, so a reload never changes the questions and answers are graded against what was shown.
26. **A quiz with zero questions counts as a pass** (empty bank or no usable cards) so a player is never blocked from their reward by missing content. The UI shows a plain "Claim reward" button for it.
27. **Quest counting.** `sessions_claimed` and `study_minutes` count at claim time; `cards_reviewed` counts per applied review or review-session card; only due cards can be reviewed (no farming). Claim is idempotent.
28. **Personal tasks are self-reported, so only 10 completions per UTC day pay XP** (counted by `rewardedAt`). Further completions still complete, with note `daily_cap_reached`. Un-completing never refunds and re-completing never repays.
29. **Review sessions** use subject "Flashcards", difficulty easy, and their claim quiz is built from the due cards.
30. **Local import mapping.** XP becomes ONE `legacy_import` ledger row (once per account, capped at 500 000, `leaderboardEligible=false`). Tasks arrive already rewarded; sessions are history only; skills are re-derived from points; avatar images, emoji pictures, streak, energy, raid counters and attribute points are NOT imported; raid history is archived in `ImportBatch.report.archive`. A repeat of the same payload hash returns the earlier report.
31. **CSV formula hardening.** Cells starting with `=`, `+`, `-` or `@` are prefixed on export and restored on import, so a spreadsheet never runs a card as a formula.

## Phase 4 (core modules: web)

32. **Import prompt behaviour.** It appears only when `localStorage['studyverse-data']` exists, never imports by itself, and writes `studyverse-data-backup-<timestamp>` first (if the browser refuses to store it, the import does not run). "Not now" lasts for the browser session. After success the player chooses: keep the old save, or remove it and all backups from this browser. The prompt never returns for an account once an import succeeded (`studyverse-import-done:<userId>`). Importing into an account that already has progress needs an explicit "merge" tick; the server enforces the same rule.
33. **Study timer uses the server's seconds.** The countdown starts from `remainingSec` in the latest response and only measures time since then with `performance.now()`; the computer's date is never read. Every response (including a refetch on window focus) re-syncs it.
34. **Focus tracking is advisory.** The browser measures time the tab was hidden or unfocused while the timer ran and sends a 0..1 ratio on finish; with under 10 s observed (e.g. just after a refresh) it sends nothing. The server clamps it.
35. **Review queue is fetched once per run** (`staleTime: Infinity`, `gcTime: 0`) so a background refetch cannot reshuffle cards mid-review; each answer carries the `dueAt` the player saw, so a double-click is harmless.
36. **Outcome screens live in page state.** After finishing or claiming, the result is held by the page so the refetch that clears the "active session" cannot wipe it before the player has read it.
37. **Explanations are never invented.** `npm run explanations:draft` writes `docs/explanations-review.json` with empty `explanation` and `approved:false`; `npm run explanations:apply` stores only approved, non-empty entries and only the `explanation` column. The owner (or an AI assistant whose text the owner reviews) fills the file.
38. **No new web dependencies in Phase 4.** Dialog, Tabs and the state views are small shared components in `apps/web/src/ui`; charts are not needed yet.

## Phase 5 (art)
- **All baseline art is original and procedural.** Why: the sandbox could not download from kenney.nl / opengameart.org / itch.io, and the CC0 packs found are 16x16 scale, which would clash with 48-96 px sprites. Alternative: vendor a pack later via manifest `image`/`sheet` entries (the components already support them and refuse non-local `src`).
- **32-colour palette** = the 9 design tokens + lighter/darker steps (`features/art/palette.ts`). The 23 extra steps were added to `styles/tokens.css` (additive; nothing existing changed) and `palette.test.ts` fails if the two ever disagree.
- **Material canvas + bake step.** Sprites are drawn with materials (skin, steel, teal...) and baked into palette-indexed grids with top-left shading and a 1px outline; flash (hit) and gray (defeat) are bake options. Why: one shading language for ~150 sprites and cheap state variants. Alternative: hand-typed grids per sprite (too slow, inconsistent).
- **Heroes are layered** (`shadow, back, body, armor, weapon`); armour and weapon layers are replaceable per item slug so equipment visibly changes the hero. `hit` is a recoil pose; the white flash is a separate `flash` option.
- **Enemies share one composer** (`sprites/enemy-kit.ts`): each enemy is one drawing function; `idle/attack/hit/defeat` (+ `phase2` for bosses) come from a pose object plus a lunge/recoil shift. Phase 2 is a material remap plus extra details (cracks, wisps, spikes), so it is cheap and always matches the idle silhouette. Defeat is `topple` (rotate), `melt` (ghosts squash to a puddle) or `collapse` (the wyrm sags).
- **Lunge and recoil are clamped by the kit** so the outline can never reach the canvas edge. Why: the first pass clipped tails, scarves and weapons on `attack`/`hit`; hand-trimming each sprite is fragile. A test now checks every enemy, state and flash variant for edge contact. Consequence: some `attack` shifts are only 1-2 px; larger lunges are the battle screen's job (Anime.js moves the whole sprite).
- **Silhouette test uses Jaccard distance >= 0.2** between idle outlines (feet row and above). A recolour scores 0 and two creatures on one template score under 0.1; the closest real pair today (Bloom Brute / Mimic Tome, both wide) is 0.27. It is a crude shape check, not a judgement of quality.
- **Item icons and rarity frames are separate manifest entries.** `ItemIcon` stacks `frame.<rarity>` (36 px) and the icon (32 px, 2 px inset). Why: a manifest entry must have one size, and either piece can then be re-drawn or replaced by a vendored pack independently. (An earlier "tile" state broke that rule; the manifest test caught it.)
- **Backgrounds are flat colour bands**, no outline or edge shading, three layers (far/mid/near) per scene so the battle screen can offset layers by whole pixels. Floor line is y=128 and the centre stays clear. Fixed scenes are 320x180, shown at integer scale; a narrower parent crops the edges instead of scaling by a fraction.
- **Effects are flat, outline-free frame sheets** (slash 4, impact 4, spark 4, heal 5, shield 4, guard-shatter 5, victory 5, level-up 6). Reduced motion holds one frame.
- **Manifest** (`features/art/manifest.ts`): `{ kind: 'grid' | 'sheet' | 'svg' | 'image', size, scale, anchor, license, source, ... }`. Gameplay and UI code only know keys (`hero.warrior`, `monster.gearwork-golem`, `weapon.quillblade`, `dungeon.archive`, `effect.slash`, `ui.flame.2`). Components accept an optional `manifest` prop so tests and tools can supply their own.
- **Sprite never throws on bad input**: unknown key, unknown state, or a non-local `src` renders an obviously unfinished labelled placeholder (never an emoji).
- **Integer scale is enforced in code**, not just by convention: `integerScale()` rounds and, in development, warns.
- **Legacy emoji avatars** (student, wizard, elf, scientist, teacher, shield) map to the six pixel busts through `LEGACY_AVATAR_EMOJI`, written with `\u` escapes so no emoji character exists in source. Phase 4's local-data import can use it.
- **Display font:** Pixelify Sans (OFL) via `@fontsource`, latin 400/600/700, imported only by the UI kit. Body font stays Lato. `--font-pixel` and `--pixel` (3px) are tokens.
- **UI kit borders are stepped box-shadows** (notched corners) and sizes are multiples of `--pixel`, so edges land on whole pixels with no image assets. Bars are fixed-size blocks, not percentage widths, for the same reason. Locked skill nodes stay focusable (`aria-disabled`) so their effect text can be read.
- **`/dev/art` is development-only.** The lazy import sits inside a function only called when `import.meta.env.DEV` is true; the production build was checked and contains no DevArtPage chunk.
- **No-emoji test scope:** scans all non-test source under `apps/web/src` with `node:fs` (Vite's `?raw` returns nothing for `.css` under Vitest). Arrows (U+2190-21FF) are allowed; emoji, dingbats, misc symbols and geometric shapes are not. The only non-ASCII symbol in the app today is the arrow in `CsvPanel.tsx`.

## Art quality pass (after Phase 5)

- **Frames are an index within a state, not new states.** `enemyStates()` is asserted to be exactly idle/attack/hit/defeat, and
  the manifest/DevArt consumers iterate states. Heroes and enemies take `frame` (idle 0-1, attack 0-2 = wind-up, impact,
  recovery). Alternative rejected: `attack-windup` etc. as states (breaks the enemy test and every state loop).
- **The still frame of `attack` is the impact.** Thumbnails, contact sheets, tests and reduced motion all show the strike
  (`STILL_FRAME` in `sprites/frames.ts`). Playback order is still wind-up, impact, recovery.
- **Heroes: new `face` and `offhand` layers.** `face` is a flat, outline-free decal so eyes/brows/mouth/glasses never disturb the
  skin shading (the shader rims every pixel next to a different material, which speckled faces). `offhand` carries the Tank's
  shield and the Scholar's book. Weapon and armour stay replaceable layers keyed by item slug.
- **Class default gear** (`CLASS_GEAR`): Warrior iron sword + leather armour, Tank iron sword + iron plate, Scholar scribe's staff
  + scholar's robe. Only used when no equipment is given; equipment still overrides.
- **Heroes stand 2 px right of the pose table origin** (`HERO_X0`; manifest anchor x 24 -> 26) so capes, bedrolls and recoil
  have room on the left. A weapon shrinks its reach until its whole drawing, widths included, fits the canvas.
- **No new palette colours.** Added flat skin tones (`fSkin7/5/3`) to MATERIALS using existing swatches; palette stays at 32.
- **Optional `rim` form shading** on `Canvas.bake` / `EnemyDef.rim`, used only on the Shadow Assassin, Inkwraith and Hollow Mage
  (near-black or flat silhouettes). Tried on the Dragon Hatchling: it looked speckled, so it was reverted.
- **Enemy frames are generic first**: idle 2 = upper body settles 1 px (2 px for bosses) with the feet planted; attack =
  coil back + squash, lunge, halfway return. Draw functions can opt in via `pose.wind` / `pose.idle2` (none do yet).
- **Unverified here:** Pixelify Sans (font files unavailable in the sandbox), real vitest/jsdom runs, eslint, `vite build`.

## Phase 5b (restyle and navigation)

- **One pixel look, reached by CSS composition.** `ui/common.module.css` keeps every class name the screens already use and now
  `composes` recipes from `features/art/kit/kit.module.css` (panel, button variants, input, entry, scroll, chip, alert,
  skeleton, rule). Why: ~55 buttons and ~17 panels across screens would otherwise be rewritten by hand (some panels are
  `<form>`/`<fieldset>`, which `PixelPanel` cannot be), with more risk to the existing tests for no visible gain. Markup,
  labels and ARIA roles did not change: all 282 earlier tests pass untouched. New structure (sidebar, HUD, login, page
  headers, bars) uses the kit components directly. Alternative: convert every JSX site to `PixelButton`/`PixelPanel`.
- **Sidebar and drawer.** Desktop: sticky left sidebar, collapsible to icons. The saved choice (`localStorage` key
  `studyverse.sidebar-collapsed`, read and written inside try/catch) wins; with no choice it starts icons-only at 1100px
  and below. At 640px and below it becomes a slide-in drawer opened from the HUD. Why 640 and not 768: the spec wants a
  drawer on phones and an icons-only sidebar on tablets, so a tablet keeps a permanent nav. The three widths stay in step
  in `layouts/useSidebar.ts` and the three `layouts/*.module.css` files (comments say so).
- **Drawer accessibility.** `ui/useFocusTrap.ts` (Tab/Shift+Tab cycle, Escape) is a second copy of what `Dialog` does inline;
  `Dialog` was left alone. While the drawer is open the page column is `inert`; closing returns focus to the menu button, and
  following a link moves focus to `<main>` (a skip link also exists). Link text stays in the DOM when only icons show
  (visually hidden + `title`), so accessible names never change.
- **HUD.** Everything comes from `GET /me` (name, level, `currentLevelXp / xpForNextLevel`, energy, streak). Energy is an icon
  plus the real count, not "pips": energy has no cap in `balance.ts`, so a fixed number of pips would misstate it. The two
  small numbers (energy, streak) use the body font because the pixel font's small "5" reads as "S"; big readouts (the
  session timer) keep the pixel font, where digits are clear.
- **XP crest.** The level number moved from the middle of the shield to a small plate at its lower right. The crest art has a
  star in the middle, which hid the number (found by looking at a rendered screenshot, not by a test).
- **Typography.** Headings and HUD use Pixelify Sans via `--font-pixel`; `--font-display` is now an alias of it. Cinzel is no
  longer imported (the dependency is still in `package.json`; remove it in session 08 cleanup). Paragraphs, inputs, quiz and
  card text stay on Lato.
- **Native controls.** `<progress>` became `PixelBar` (same `progressbar` role and name). Checkboxes are sunken parchment
  squares with a gold block when ticked; radios are a pixel circle so they never look like checkboxes. The select arrow and the
  radio art are inline SVG data URIs, whose colours must be literal hex (CSS variables cannot reach a data URI); each is
  commented with the token it matches.
- **Fieldset legends** are laid out as a normal first line (`float` trick in `global.css`) because the kit draws frames
  outside the box and a default legend straddled the frame line.
- **Login** is a title screen: the existing camp scene (`scene.camp`) at the smallest whole scale that covers the window
  (2 to 6), a parchment card on top. Still one `<h1>Log in</h1>`, same labels, same alert behaviour.
- **Contrast.** Computed from `tokens.css`, not assumed. Lowest pairing used is gold-500 on forest-700 at 5.2:1; everything else
  is 6.4:1 or higher (all AA for body text).
- **Screenshot tool.** `npm run shots -w apps/web` starts Vite against a mocked API and Supabase session
  (`scripts/mock-api.mjs`, made-up data, dev only) and screenshots every route at 390 / 768 / 1280, then checks each for
  horizontal overflow, console errors and tap targets under 40px. It needs a Chromium Playwright can launch
  (`npx playwright install chromium`, or `PW_CHROMIUM_PATH`). Output is in `docs/screens/`. ESLint gets a block for these
  `.mjs` files (Node + browser globals, because `page.evaluate` callbacks run in the page).
- **Verified here (earlier notes said these could not run):** `npm install`, `build:shared`, ESLint, `tsc`, real Vitest with
  jsdom (including `Sprite.frames.test.tsx`), `vite build`, and Chromium rendering. Still not run: the API workspace tests
  (they need `prisma generate`, and nothing in the API changed).


## Phase 5c (game-style navigation: HUD, hotbar, Menu, summary)

Replaced the 05b sidebar and drawer with a HUD, a bottom hotbar, a Menu overlay and `GET /api/v1/summary`.

1. **Summary shape = 05c's, plus three fields.** `GET /summary` returns the five specified values and also `serverNow`, and the active session carries `pausedAt` and `remainingSec`. Why: a paused session's countdown must freeze at the pause moment, and the HUD must count down from the server's clock (the same rule as the Study screen), never the browser's. Counts only: no card text, no quest names, no titles. Alternative: the exact 05c shape, which cannot freeze a paused timer.
2. **The summary is read-only.** It does not create quest rows and does not abandon stale sessions (unlike `GET /sessions/active`, which writes). A running session older than `staleOpenHours` (or paused that long) is simply not reported, using the same cutoff as `abandonStale`. A session that is finished but still waiting for its claim quiz is NOT reported (it has no countdown); the Study screen itself still resumes it. Why: a badge endpoint called on every screen should never write.
3. **`BALANCE.raid.energyCost = 3`** was added for the Adventure pip ("energy >= 3"). Session 06 spends it. Until 06 the Adventure route is still "Coming in a later phase", and the pip only says the player has enough energy.
4. **One place refreshes the badges.** `createQueryClient()` (`lib/queryClient.ts`) invalidates `['summary']` after *any* successful mutation, so no screen needs wiring and 06/07 get it for free. Cost: one small extra request per write. Alternative: invalidate in every `onSuccess` (about 20 sites, easy to miss one).
5. **Sign-out moved from the HUD to the Menu** (05c puts it there). The HUD is slim (64 px desktop, 56 px phone) and has no Log out button. Tests replaced for this are listed in `docs/HANDOFF-05C.md`.
6. **Hotbar link names use `aria-label`** ("Library, 12 cards due"). The first attempt put the hidden text in a visually hidden child, and Chromium joined flex children with a space ("Library , 12 cards due"). The label still starts with the visible text (WCAG 2.5.3). The drawn badge is `aria-hidden`; there is no `aria-live` anywhere in the hotbar.
7. **Badges are calm by construction:** gold on charcoal, never red; none for zero; no streak wording; the Adventure badge is a pip, the Study badge a "Resume" pill plus a ring on the icon. Counts above 9 are drawn as `9+`, but the spoken number is exact.
8. **Hotkeys (WCAG 2.1.4).** `1`-`5` go to the hotbar slots, `M` opens the Menu, `H` opens Hero (`/camp`). Ignored while a text-like field, textarea, select, `contenteditable` or `role=textbox` has focus; with Ctrl, Alt or Meta; on key repeat; while IME composition is active; while a modal dialog (`[aria-modal=true]`) is open; and while the Menu is open. A focused checkbox, button or link does not block them. The on/off switch is in the Menu; it is stored under `studyverse.hotkeys` (`'0'` = off) inside try/catch and defaults to on if storage is blocked. Session 07 should mirror it in Settings.
9. **Menu overlay = a modal dialog, not a route.** Credits is a disclosure inside the overlay (no new route, 05c rule). It states what is true today: all art is original; Pixelify Sans and Lato are used under the SIL OFL 1.1. **Owner: please confirm the Lato licence line** against `node_modules/@fontsource/lato/LICENSE` (written from knowledge, not checked here; `ASSETS.md` had no Lato row, one was added).
10. **The shell makes everything behind the overlay `inert`** (one wrapper holds HUD, page and hotbar; the overlay is a sibling). Focus returns to the Menu slot on dismiss, and to `<main>` when a link was followed.
11. **Energy stays a count, not pips** (the 05b HUD decision: energy has no cap in `balance.ts`, so pips would misstate it). 05c's HUD list says "energy pips"; the number is the honest version.
12. **HUD portrait.** It is the equipped bust shown through an 18 x 18 window of a gold frame (`ui.portrait-frame`), at 2x = 48 px, so the HUD fits 64/56 px. The window crops the 32 px busts and 40 px class portraits at fixed corners (`HeroPortrait.tsx`). Level shows as "Lv N" in the name on desktop and as a small plate on phones (the name line is visually hidden there but still read by screen readers). A gold "!" on the frame marks unspent skill points.
13. **Latent mismatch found:** the API's avatar presets (`student, mage, ranger, scientist, teacher, guardian`, `packages/shared/src/avatars.ts`) differ from the art's bust ids (`student, wizard, elf, scientist, teacher, knight`). `portraitSource()` maps them and a test asserts every preset reaches a real manifest entry. Session 07 (Camp) should unify the two lists. Uploaded avatars (`avatarUrl`) are not shown in the HUD yet (the Camp upload feature is session 07).
14. **Destination names vs page titles.** The hotbar and Menu use the game's words (Home, Quests, Study, Library, Adventure, Progress, Hero). The three *placeholder* pages were retitled to match (`/camp` is "Hero", `/dungeons` is "Adventure", `/stats` is "Progress"; `router.test.tsx` updated). The three *real* screens keep their 03-phase headings ("Quest Board", "Study Sessions", "Lab") so their tests stay valid; aligning them ("Library" etc.) is a follow-up for 07.
15. **Layout facts.** The hotbar is fixed to the bottom; `<main>` reserves `--hotbar-h` plus the safe-area inset; `html:has([data-hotbar])` sets `scroll-padding-bottom` (and `[data-hud]` sets `scroll-padding-top`), so a focused field is never hidden. The hotbar and HUD only exist inside `AppLayout`, so `/login` and `/battle/:id` have neither, with no extra code.
16. **`sessionElapsedSec` moved** to `services/sessionTime.ts` (still re-exported from `sessions.ts`), so the summary's pure part does not import the sessions service.
17. **Verification environment.** This session's sandbox had no network, so `npm install`, ESLint, Vitest and `vite build` could not run. Instead the real components were bundled with esbuild (with small stand-ins for the router, query client and API) and driven in Chromium by Playwright: `docs/05c-verification/`. That is evidence about the components, **not** a substitute for the project's own checks (see the handoff).
18. **Home hub (P1).** `scene.hub` is the camp WITHOUT its tents, board, fire, wagon and gate (the old `scene.camp` is unchanged); `prop.*` sprites (seven, with states) are painted in scene coordinates and cropped to a box, so they line up exactly. The gate sits behind the trees (far layer), the rest in front of the meadow; the pine at x=286 is left out of the hub so it does not hide the gate. Props are links (aria-label = "Library wagon, Library, 12 cards due"); hit areas grow to at least 44 px; hover/focus lifts a prop by one art pixel and adds an outline; the scene is 2x on wide screens and 1x on phones. The campfire is not a link; its flame is the streak flame level. States come from `/summary` and `/me` only (`features/hub/hubState.ts`).
19. **Travel wipe** is a thin gold bar that steps across in whole pixels (a rounded eighth of the width, 300 ms), on top of the page with `pointer-events: none`, so content is never delayed or hidden; not drawn under reduced motion.

## Phase 5c continuation (second sandbox, still no network)
1. **`docs/**` is excluded from ESLint.** The 05c verification harness (`docs/05c-verification/`) uses `any` in stubs, CommonJS scripts and
   browser/Node globals; linting it would fail `npm run lint` for reasons unrelated to product code. Alternative: add per-folder globals and
   fix every stub; rejected as effort without value.
2. **"Skip scene" link has a 44 px minimum height in every state.** It was parked off-screen at 26 px tall, which the shots audit
   (and the 05c 44 px intent) rejects. Kept the off-screen technique and the static-on-focus behaviour. Known minor trade-off: when it
   takes focus it is in the flow and shifts the scene down by its own height; an overlay variant is possible later.
3. **`.env.example` files restored.** The zip protocol strips `.env*`, which also removed the two committed `.env.example` files
   (git showed them as deleted). They hold only public values and placeholders. Future zips must exclude `.env` and `.env.*` **except** `.env.example`.

## Desktop design review (after 05c, owner feedback on the 1280 px render)
1. **Reverses 05c for desktop only.** 05c rejected a sidebar ("a list of links beside a page"). Measured result of following 05c's desktop numbers: 156 px of an 800 px viewport spent on a HUD and a bottom tab bar, a 640 px column in a 1280 px window, three misaligned axes. Width is plentiful on a desktop and height is scarce, so from 1024 px up the player card and the navigation share one framed left panel and the page gets the full height. It is a character panel, not a link list: same routes, `aria-current`, hotkeys, badges and Menu; phones and tablets keep the 05c model. Alternative rejected: a single top bar with the hotbar in the middle (reads as a website toolbar, which the owner explicitly did not want).
2. **The layout is chosen in JavaScript** (`useMediaQuery(DESKTOP_QUERY)`), so there is one set of focusable elements, never two copies hidden by CSS. Variants are `Hud variant="bar|panel"` and `Hotbar variant="bottom|rail"`; `data-layout`, `data-rail`, `data-hud`, `data-hotbar` and `data-variant` are the test hooks.
3. **No currencies were added.** The owner asked for "currencies"; `04-rpg-design-spec.md` says "Do not add extra currencies in this version". The HUD shows Energy, Streak, XP/level and unspent skill points (only when > 0, from `/summary`).
4. **Resources are labeled** ("Energy", "Streak" visible; screen-reader text unchanged). The key caps use the body font: the pixel font's 5 reads as an S.
5. **Panel width 16.5 rem (264 px) with a 17-segment XP bar**: segments are 9 px with a 3 px gap, so 17 fill the panel's inner width exactly and stay on whole pixels.
6. **Narrow phones (<= 380 px):** 4 XP segments beside the session chip and 8 px side padding; a 5th segment was clipped and made an 80% bar look full.
7. **Menu overlay** is dimmed with `color-mix` (the game stays faintly visible behind a pause menu), centred with auto margins (does not clip a tall card), and a full-height sheet on phones.
8. **Home** is a grid: scene (2x, 640 px) left and the dashboard column right from 1280 px, stacked and width-matched below. The placeholder label now says "Session 07" (the dashboard is built in session 07).
9. **Review harness:** `apps/web/scripts/design-shots.mjs <label> [screen]` writes `docs/redesign/<label>/` (screenshots plus `metrics.json`) at the five review viewports and fails on overflow or HUD/hotbar clipping. `docs/redesign/before` is the pre-redesign set kept for comparison.
